> Thanks for making time. A quick summary of the last two days.

> I built a pipeline that scores minimal pairs with minicons, the same way TurBLiMP's code does. On MultiBLiMP's 50 Uzbek pairs, the Uzbek Goldfish model gets all 50 right and Qwen 2.5 0.5B gets 41. So that set is too small and too easy to separate models, which is one reason UzBLiMP is needed.

>
> I also scanned a 64-million-word corpus for candidate sentences, tested TurkicNLP, and ran a tiny three-alphabet pilot. One early lesson: models that never saw ğ, ş and ç turn them into unknown tokens, so the reformed alphabet only makes sense with byte-level models.

## 3. Decisions: Kattabek's positions (2026-10-06) and what to confirm with Yana

1. **Framing: benchmark.** Publish on arXiv for early feedback; Yana gives feedback and guidance.
   - *To check:* arXiv normally wants each submitter to use **their own account**, and first-time submitters get an **endorsement** from an established arXiv author. So the usual route is: a local professor endorses you (and may be a co-author), and you submit from your own account, rather than through theirs. Ask Yana how she'd do it.
2. **Alphabets: keep all three.** Latin vs Cyrillic is the main comparison. Reformed Latin is a small extra, run only on models whose tokenizer can encode ö/ğ/ş/ç (byte-level), with `<unk>` rates reported.
   - *Suggestions (Claude):*
     - **Screen models first:** run every candidate model's tokenizer over the pairs and include it in the reformed condition only if it produces 0 `<unk>`.
     - **Frame it as "an unseen spelling":** no model has seen reformed Uzbek yet (approved Sept 2026), but byte-level models have seen ö/ğ/ş/ç in Turkish and Azerbaijani. Whether grammar knowledge carries over to an unfamiliar spelling is a clean, interesting question.
     - **Report separately** the pairs where the tested letter itself changes (e.g. row 7 *oʻrtogʻim*, gʻ→ğ) and the pairs where only other letters change.
     - **Keep the ≤1B limit for development,** then ask Yana which larger models to add for the paper. Newer and larger models are more likely to handle the new letters.
3. **Which phenomena first?** Kattabek leans towards Uzbek-specific ones (novelty).
   - *Suggestion (Claude):* a mix, weighted towards Uzbek-specific. Start with 3 Uzbek-specific ones (no plural after numerals, possessive agreement, *hech* + negation) plus 2 that match TurBLiMP (lexical case, *oʻz-* agreement). The shared ones let the paper say "compared with Turkish…", which reviewers will ask for. Then add Uzbek-specific ones (q→gʻ, suspended affixation with *-gan*).
4. **Linguists and credit:** local professors who help publish and verify get credit.
   - *To check:* ethics approval wouldn't come from Yana. It comes from an ethics committee at the institution that runs a human-judgment study (if we do one, like TurBLiMP's 30-speaker survey). At minimum, use informed consent like TurBLiMP App B. Ask Yana whether her or the professor's institution would require approval. Agree authorship vs acknowledgment early, before anyone starts work.
5. **TurkicNLP: settled.** Kattabek talked to Sherzod Hakimov; he's happy for it to be used and extended. Plan: pin the version, verify outputs, contribute the small fixes first (`notes/turkicnlp.md`).
